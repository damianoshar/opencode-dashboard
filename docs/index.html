See and repair your OpenCode database
from the browser.

A local FastAPI dashboard for opencode.db. It browses every session, project, directory and backup, shows the health of the database at a glance, and turns the maintenance chores - backup, checkpoint, vacuum, move, export, delete - into explicit, audited operations.

Eight views, one database

Every tab has its own URL, so a page can be bookmarked, reloaded and shared.

Overview

Row counts for every table, database size, free pages, WAL stats, tokens and cost, plus the health checks that matter: orphan messages, orphan events and seq-lag sessions.

Sessions

Every session_v2 row with filters for project, directory, agent, model, state, root/child/fork, date range and free text. Table, grid and compact views, a message drawer, and CSV / JSON export.

Projects

The project registry with worktree, VCS, session and message counts, cost and whether the directory still exists on disk. Click a directory to filter the session list.

Directories

Every directory the app knows about, merged from session_v2, the legacy session table, project, project_directory and worktree, with orphan detection.

Backups

Every backup file that can be found - OpenCode data dir, dashboard backups, recovery workspaces - with size, mtime and a one-click quick_check and foreign_key_check.

Maintenance

Backup, verify, checkpoint, vacuum, prune projects, prune orphan counters, move sessions, export Markdown, export and restore a bundle, repair event sequences, delete sessions and projects.

Schema

Every table with its columns, indexes and foreign keys, a row browser, and a read-only SQL console that only accepts SELECT, WITH and PRAGMA.

Storage & Logs

Size and file counts for the OpenCode data dir, logs, storage, snapshots, worktrees, tool output and the dashboard's own folders, plus a log tail viewer.

Install and run

The dashboard finds the OpenCode database by itself. Point it somewhere else with an environment variable if you need to.

PowerShell
git clone {{REPO_URL}}.git
cd opencode-dashboard
python -m pip install -r requirements.txt

.\run.ps1                 # http://127.0.0.1:8791
.\run.ps1 -Port 9000      # a different port
.\run.ps1 -ReadOnly       # refuse every mutating endpoint
Any platform
python -m pip install -r requirements.txt
python -m dashboard.app

Nothing happens by accident

A dashboard that can delete sessions has to be boring about it.

Explicit confirmation

Every mutating endpoint refuses to run without {"confirm": true} in the request body, and every run is written to data/audit.log.

Typed cascade

Deleting a project cascades into its sessions. The second step asks you to type DELETE - anything else cancels, so a stray click can never wipe a project.

Read-only default

The database is opened read-only. The service is never stopped, and -ReadOnly blocks the maintenance endpoints entirely.

Backup before damage

The backup operation is an SQLite online backup with a manifest of row counts, safe to run while OpenCode is writing.

Recoverable mistakes

scripts/restore_sessions.py puts sessions that went missing back into the live database from a backup and realigns their event counters.

No surprises in the API

A session is removed through the real session.remove operation first. If that call fails, nothing is purged and the failure is reported.

The HTTP API

The UI is a client of the same JSON API. Interactive documentation lives at /api/docs.

EndpointWhat it does
GET /api/healthdatabase path and health
GET /api/statsaggregates for the overview
GET /api/sessionsfiltered, sorted, paginated sessions
GET /api/sessions/{id}one session with its messages
GET /api/projectsthe project registry
GET /api/directoriesevery known directory
GET /api/backupsevery backup that can be found
GET /api/schematables, columns, indexes, foreign keys
POST /api/maintenance/{operation}backup, vacuum, move, delete, export, repair…
GET /api/export/{kind}.csvCSV export of the filtered set

Command line companions

verify_live.py

A read-only health report: quick_check, foreign keys, row counts, duplicate worktrees, seq-lag sessions and orphan counters.

ui_check.py

A Playwright check of the routing, the selection UI and the delete flow. It refuses the destructive prompt by design.

restore_sessions.py

Inserts sessions that are missing from the live database from a backup. It never deletes anything.
